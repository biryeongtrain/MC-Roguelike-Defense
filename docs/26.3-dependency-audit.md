# Minecraft 26.3 의존성 조사

조사일: 2026-09-29 KST. 대상: `minigame-template`, `main`, `758eebe00149fa3b3bca3d08714c9de5e20d1a70`.

> 후속 업데이트: 이 문서는 새 Maven 배포 이전의 조사 기록이다. 이후 `repo.biryeong.kim`에서 Minigame Lib `1.0.2+26.3`, GCB-server `1.2.0+26.3`, Apel `0.1.5+26.3` JAR을 확인했다. GCB-server는 Packet Tweaker 의존성을 제거했다. 아래 미포팅 판정은 당시 상태이며 현재 선택 버전은 프로젝트의 `build.gradle`과 `gradle.properties`를 따른다.

후속 포팅은 `codex/port-26.3` 브랜치에서 완료했다. Java 25, Loom 1.18.2, 재생성한 Gradle 9.7.1 Wrapper로 `test runGameTest build`가 성공했다(JUnit 1개, 필수 GameTest 2개). 배포 JAR을 외부 필수 모드만 있는 별도 서버에 설치해 `Done`과 리소스팩 생성 성공도 확인했다. 테스트 서버는 `stop`으로 종료했다.

- 결과물: `build/libs/minigame-template-1.0-SNAPSHOT+26.3.jar`
- SHA-256: `7449d90c565f9748c26bd04a84e2270882c825687a394da6f90c06eccdec1555`
- 빌드 로그: `/tmp/minigame-26.3-build.log`
- 배포 JAR 실행 로그: `/tmp/minigame-template-26.3-runtime-20260929/console.log`
- GCB-server·Minigame Lib·Permissions API는 JAR에 포함, Apel은 기존처럼 별도 설치 대상이다.
- 최초 GameTest 실행의 `server.properties` 파일 부재 메시지는 기본 파일 생성 후 테스트 통과로 이어졌다. 배포 JAR 서버 실행에는 ERROR가 없었다. YACL refmap 및 Resourceful Lib 클라이언트 Mixin 경고는 남아 있다.
- 클라이언트 접속·시각 효과와 각 라이브러리의 모든 기능은 검증하지 않았다.

**직접 포팅 대상은 Minigame Lib, GCB-server, Apel 3종이다. GCB-server에 포함된 Packet Tweaker도 함께 처리해야 한다.**

26.1·26.2라는 버전 표기만으로 미지원 판정을 하지 않았다. 해당 빌드 6종을 최신 의존성과 함께 실제 Minecraft 26.3 전용 서버에 설치해 초기 구동을 확인했다. 이들은 아래 검증 범위에서 포팅 차단 목록에서 제외한다. 모든 기능과 클라이언트 표시까지 검증했다는 뜻은 아니다.

## 2. 26.1·26.2 빌드로 26.3 초기 구동을 확인한 프로젝트

다음 6종을 동시에 설치한 26.3 서버가 `Done`에 도달했다. 서버 측 클래스·메서드 참조도 대조했으며, 확인된 미해결 호환성 오류는 없었다. 따라서 **버전에 `26.3`이 없다는 이유로 추가 포팅 대상으로 분류하지 않는다.**

| 프로젝트 | 현재 → 검증한 버전 | 검증 JAR의 Minecraft 조건 | 배포 근거 |
|---|---|---|---|
| Sidebar API | `0.5.1+1.21.1` → **`0.6.0+26.1`** | `>=1.20.3-` | [Maven](https://maven.nucleoid.xyz/eu/pb4/sidebar-api/maven-metadata.xml) |
| Map Canvas API | `0.5.1+1.21.5` → **`0.9.1+26.2`** | `>=26.1-` | [Maven](https://maven.nucleoid.xyz/eu/pb4/map-canvas-api/maven-metadata.xml) |
| Player Data API | `0.8.0+1.21.6` → **`0.11.0+26.2`** | `>=26.1-` | [Maven](https://maven.nucleoid.xyz/eu/pb4/player-data-api/maven-metadata.xml) |
| Map Templates | `0.2.2+1.21.6` → **`0.3.2+26.2`** | `>=26.1` | [Maven](https://maven.nucleoid.xyz/xyz/nucleoid/map-templates/maven-metadata.xml) |
| DialogUtils | `1.4.0+1.21.6` → **`1.7.5+26.1`** | `>=1.21.9-` | [Maven](https://repo.biryeong.kim/releases/de/tomalbrc/DialogUtils/maven-metadata.xml) |
| Avatar Renderer | `1.0.6+1.21.8` → **`1.0.8+26.1`** | `*` | [Maven](https://repo.biryeong.kim/releases/de/tomalbrc/avatar-renderer/maven-metadata.xml) |

이 판정은 **검증한 전체 조합**에 대한 것이다. 특히 다음 내장 의존성을 그대로 고립시켜 사용하는 조합은 검증하지 않았다.

- DialogUtils 내장: Map Canvas `0.8.0+26.1`, Placeholder API `3.0.0-beta.2+26.1`. 테스트에서는 각각 `0.9.1+26.2`, `3.2.0+26.3`이 선택됐다.
- Avatar Renderer 내장: Polymer Autohost/Resource Pack `0.16.0-pre.2+26.1-rc-2`, Placeholder API `3.0.0-beta.2+26.1`. 테스트에서는 Polymer `0.18.2+26.3`, Placeholder API `3.2.0+26.3`이 선택됐다.
- DialogUtils 공식 소스의 버전은 `1.8.4+26.1`이지만, 이번에 검증한 배포 JAR은 현재 프로젝트의 Maven에서 구할 수 있는 `1.7.5+26.1`이다. 소스 버전만 보고 미검증 JAR을 추천하지 않았다.

정적 참조 검사에서 DialogUtils의 `getPacketContext()` 2곳은 원본 Minecraft JAR에 없는 것으로 잡혔다. 확인 결과 Fabric API의 `ConnectionMixin`과 `ServerCommonPacketListenerImplMixin`이 제공하는 메서드였다. 이를 포팅 결함으로 세지 않았다. 이 검사는 모든 실행 경로·리플렉션·클라이언트 전용 코드의 호환성을 보장하지 않는다.

## 3. BIL은 미포팅이 아니라 배포 경로와 패키징을 바꿔야 함

현재 좌표는 `de.tomalbrc:blockbench-import-library:1.7.0+1.21.6`이며, 프로젝트에서 사용하는 Maven에는 이 오래된 버전만 있다. Modrinth 조회도 `2.0.5+26.1`까지만 보여 최신 상태를 대표하지 못했다.

그러나 공식 GitHub에는 **`2.2.0+26.3-rc-3`** JAR이 배포되어 있다. 파일명은 RC 대상이지만 JAR의 Minecraft 조건은 `>=26.2`이며, 이번에는 **정식 Minecraft 26.3**에서 서버 초기 구동과 리소스팩 생성을 확인했다. GitHub 릴리스의 `prerelease` 플래그는 false다. 정식 26.3 이름의 다른 파일로 바꿔 설명한 것이 아니라 이 정확한 RC 표기 JAR을 검증했다.

- [공식 배포 페이지](https://github.com/tomalbrc/blockbench-import-library/releases/tag/v2.2.0%2B26.3-rc-3)
- [검증한 바이너리 JAR](https://github.com/tomalbrc/blockbench-import-library/releases/download/v2.2.0%2B26.3-rc-3/blockbench-import-library-2.2.0%2B26.3-rc-3.jar)
- [현재 프로젝트 Maven 목록](https://repo.biryeong.kim/releases/de/tomalbrc/blockbench-import-library/maven-metadata.xml)

**추가 필수 의존성: `me.lucko:fabric-permissions-api:0.7.0`.** 이 BIL 릴리스 JAR에는 해당 라이브러리가 포함되지 않았다. 빠진 상태에서는 명령 등록 중 다음 오류로 서버 로딩이 실패했다.

```text
Caused by: java.lang.NoClassDefFoundError: me/lucko/fabric/api/permissions/v0/Permissions
    at de.tomalbrc.bil.util.Permissions.require(Permissions.java:14)
    at de.tomalbrc.bil.command.BILCommand.register(BILCommand.java:10)
```

Maven Central의 `0.7.0`을 별도로 추가한 뒤 통과했다. [배포 메타데이터](https://repo.maven.apache.org/maven2/me/lucko/fabric-permissions-api/maven-metadata.xml)와 [공식 Modrinth 배포 목록](https://api.modrinth.com/v2/project/fabric-permissions-api/version)에서도 26.3 지원을 확인했다.

향후 실제 포팅 시 BIL의 새 JAR을 빌드에서 안정적으로 가져올 배포 경로를 마련하고, Permissions API도 명시적으로 설치 또는 번들해야 한다. 이번 조사에서는 Maven 업로드나 프로젝트의 의존성 변경을 하지 않았다.

## 5. 검증 범위와 재현 자료

기존 프로젝트는 Minecraft `1.21.8`, Mojang 공식 매핑, Java 컴파일 대상 `21`, Gradle Wrapper `9.2.1`, Loom `1.15-SNAPSHOT`, 서버 전용이다. 조사 시작 시 작업 트리는 깨끗했다. CodeGraph 인덱스와 MCP는 없었으며 새 인덱스를 만들지 않았다.

26.3 검증은 프로젝트를 수정해 빌드한 것이 아니라 **선정한 배포 의존성 JAR들을 설치한 별도 Fabric 서버**에서 수행했다.

- Minecraft: 정식 `26.3` — [Fabric 공식 게임 메타데이터](https://meta.fabricmc.net/v2/versions/game).
- Fabric Installer `1.1.2`, Loader `0.19.5`, Fabric API `0.161.0+26.3`.
- 실행 JVM: GraalVM Java `25.0.2`.
- 임시 경로: `/tmp/minigame-26.3-dependency-audit-20260929`.
- 바인딩: `127.0.0.1`, 임의 포트. 새 `audit-world` 사용.
- 로딩 결과: 중첩 모듈 포함 **89 mods**, 서버 `Done` 확인.
- `/polymer generate-pack`: 성공. `polymer/resource_pack.zip` 생성, 46,018 bytes.
- `stop` 명령으로 테스트 서버 정상 종료, 프로세스 종료 코드 `0`.

```text

[14:17:10] [Server thread/INFO]: Done (0.175s)! For help, type "help"
[14:18:52] [Server thread/INFO]: System chat: [Polymer] Resource pack created successfully! You can find it in game folder as polymer/resource_pack.zip
```
